# 验证矩阵与证据

## 根据差异选择检查

| 变更面 | 最低证据要求 |
| --- | --- |
| 仅 Skill/文档 | Skill 快速校验；修改脚本时运行自测；检查链接/路径；运行变更守卫 |
| `Share/Analyzer` 或源生成器 | 目标项目测试/构建，以及代表性使用方构建和诊断行为检查 |
| `DotNet` 或 `Share` C# | 将警告视为错误的定向项目/解决方案构建；可用时运行聚焦测试 |
| Unity C# | 通过已发现的 Bridge 命令获取 Unity Editor 编译结果和 Error 日志；运行聚焦测试/行为检查 |
| `.asmdef`、包、宏定义、link/AOT | Unity 导入/编译、受影响模式/平台构建证据，以及锁文件/引用审查 |
| 场景/预制体/ScriptableObject/导入器 | 通过 Bridge 回读层级/属性/导入设置、Unity 编译/导入结果和 Error 日志 |
| UI/视觉资源 | 目标 GameView 分辨率/宽高比、截图/回读、输入流程、关闭/重新打开生命周期和 Error 日志 |
| Luban/Excel/本地化 | 导出/检查命令、生成差异来源、唯一性/结构验证、使用方编译/加载 |
| Proto/消息 | 生成器、操作码/契约审查、生成差异、客户端/服务端使用方构建、兼容性测试 |
| 资源集合/构建 | 规则刷新、分组/路径审查、构建或加载冒烟测试、输出清单审查 |
| 性能 | 相同场景下可复现的前后 Profiler 采集 |

共享代码、协议、持久化、并发、资源生命周期或跨模块变更需要扩大覆盖范围。

## 运行仓库守卫

从仓库根目录运行：

```powershell
python .agents/skills/gdk-development-workflow/scripts/validate_changes.py
git diff --check
git diff --stat
```

提交前立即使用 `--staged`，分支/PR 差异使用 `--base <ref>`。只有有意解决或豁免全部警告后，才使用 `--strict`。

## 构建正确的变更面

先使用能够证明改动面的最小命令，再针对共享契约扩大范围：

```powershell
dotnet build Kit.sln
dotnet build DotNet/DotNet.sln
```

如果只修改了一个独立工具，构建对应的 `.csproj`。存在生成的 `Unity/Unity.sln` 时，只将其作为额外的 IDE/编译器检查。它无法证明导入、序列化、域重载、Player 宏定义或场景状态，因此绝不能替代 Unity Editor 编译。

## 通过运行时发现验证 Unity

阅读 `unity-agent-bridge.md`。发现当前命令集，再从其返回结构中选择编译、日志、测试、检查、播放模式、输入或采集命令。除非命令已在当前会话中被发现，否则不要在计划中写入静态命令名。

多步骤项目流程优先使用聚焦的无参 `AgentCallable` 方法或 Unity Test Framework 测试，避免多次脆弱的有状态交换。依次准备、执行、断言；失败时抛出包含预期值/实际值的异常，并在 `finally` 中清理临时状态。

## 测试失败路径

覆盖主要成功路径，以及风险最高的失败或取消路径。相关情况包括：

- 重复打开/关闭、显示/隐藏、重连、重新加载和关闭；
- `await` 后取消以及所有者销毁；
- 重复或乱序的网络消息；
- 配置缺失/格式错误和过期缓存；
- 包/生成器重复运行及幂等性；
- 场景切换、域重载、热更新和对象池复用；
- 资源加载失败，以及替换后的资源释放。

## 如实解读结果

- 命令退出码为零只证明该命令成功。
- 生成差异只证明生成流程运行过，不证明数据正确。
- 编译通过只证明类型和分析器检查，不证明运行时生命周期或视觉效果。
- 截图只证明一个渲染状态，不证明交互或所有分辨率。
- 必须用基线证据区分既存的无关错误和本次回归。

## 报告证据

使用以下紧凑交接结构：

```text
变更：<行为和归属文件>
已验证：<实际执行的命令/Bridge 检查及结果>
未验证：<无法执行的检查及原因>
风险：<迁移、兼容性、资源、性能或无>
```

绝不将不可用的检查标记为通过。检查失败时，提供首个可操作错误，并说明该错误是否在变更前已存在。
