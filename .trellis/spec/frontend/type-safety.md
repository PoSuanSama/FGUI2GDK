# Unity C# Type Safety

Unity code targets the language/runtime configured by the nearest assembly and `Unity/Directory.Build.props` (currently C# 11 by repository convention). Respect `.asmdef` boundaries before adding a reference.

## Local Patterns

- Prefer typed generic APIs such as `OpenUIForm`, `ShowEntity<T>`, `AddUIFormComponentAsync<T>`, and ET typed handlers.
- Keep ET attributes and lifecycle interfaces consistent with the component: `[ComponentOf]`, `[EntitySystemOf]`, `IAwake`, `IDestroy`, and UGF lifecycle markers.
- Use generated enums/IDs for UI, entity, scene, sound, and configuration identities.
- Validate `object userData` at lifecycle boundaries; do not spread untyped values deeper into the feature.
- Keep nullable/absence behavior explicit for lookups and asynchronous loads.

Generated sources under `Generate/`, `<auto-generated>` files, and FairyGUI official binding sources are not edit points. Update Excel/Proto/FairyGUI XML/generator input and regenerate.

Do not weaken type safety with reflection, string type names, hard-coded IDs, or broad assembly references merely to avoid following an existing typed extension point.
