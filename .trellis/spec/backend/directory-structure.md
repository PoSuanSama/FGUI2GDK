# Server Directory Structure

## Ownership Boundaries

- `DotNet/App/`: executable entry points and composition only.
- `DotNet/Core/`: low-level ET infrastructure with a narrow dependency surface.
- `DotNet/Model/`: server entities and state; behavior belongs in systems.
- `DotNet/Hotfix/`: hot-reloadable behavior, message handlers, and services.
- `DotNet/Loader/`: startup and loading behavior.
- `DotNet/ThirdParty/`: explicit external integration boundary.
- `Share/Analyzer/`, `Share/SourceGenerator/`, and `Share/Tool/`: analyzers, generators, and development tools.

The Admin and Agent implementations demonstrate feature grouping under `DotNet/Hotfix/Server/Admin/` and `DotNet/Hotfix/Server/Agent/`. Message entry points such as `Admin2S_ReloadHandler.cs` remain thin and call components/services for owned behavior.

## ET Shape

ET state types live in Model; `[EntitySystemOf]` systems and `[MessageHandler]` handlers live in Hotfix. Startup follows the `AInvokeHandler<FiberInit, UniTask>` pattern in `DotNet/Hotfix/Server/Admin/FiberInit_Admin.cs`.

## Avoid

- Business logic in `DotNet/App/` or Loader entry points.
- Server-only dependencies in client assemblies.
- Adding broad assembly references to reach one helper.
- Editing a `Generate/` file or `<auto-generated>` output instead of its Luban/Proto/generator input.
