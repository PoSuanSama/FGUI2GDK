# FairyGUI PSD 语义导入与资源组件复用

## 目标

建立一条面向未来设计稿的通用流程：当任意命名混乱、分组错误或层级混乱的 PSD/PSB 到来时，
AI 能在不破坏原文件的前提下重建设计语义，并查询届时已有的 FairyGUI 公共组件库与公共图片库。
生成结果优先复用稳定组件/图片引用、九宫格/平铺元数据和实例镜像；只有无法兼容复用的内容才新增
图片或组件，从源头抑制资源与组件冗余。

## 用户价值

设计师无需先严格整理 PSD 图层，AI 也不会把每一层机械切图。导入结果能解释“为什么复用、为什么
新建、如何拉伸或镜像”，并通过 FairyGUI 预览和像素/结构检查证明视觉与行为契约成立。

## 已确认事实

- 本任务设计未来通用能力，不以当前仓库现有图片、PSD 数量或命名质量为输入基线，也不负责迁移
  现有资源。
- FairyGUI 图片资源原生支持九宫格和平铺缩放，图片实例原生支持水平/垂直/双向镜像；复用不需要
  生成额外镜像位图。
- FairyGUI 组件与图片可以通过稳定 package/resource ID 跨包引用；公共库应成为可检索的事实来源，
  而不是依赖文件名猜测。
- PSD 只能提供视觉与部分文本/图层信息，不能可靠证明按钮行为、controller 状态或业务插槽；组件
  复用必须同时满足结构/行为契约和视觉要求。
- 可评估 `psd-tools` 作为 PSD/PSB 解析器；依赖引入、版本锁定和许可证记录需在实施前通过风险门禁。

## 需求

### R1. 无损 PSD 解析与语义重建

- 输入支持未来提供的 PSD/PSB；原文件只读，禁止自动重命名、合层、覆盖或删除图层。
- 解析并保留文档尺寸、图层唯一 ID/原始路径、层叠顺序、组、可见性、边界、透明度、遮罩/剪贴、
  混合模式、文字和可读取效果；不支持的效果必须标记为 `rasterize`/`proposed-new`，而不是静默丢失。
- AI 基于全图、局部缩略图、几何、重复模式和文本上下文建立语义树，处理 `图层 1`、重复名、错误
  分组和纯视觉装饰；规范名与原始图层 ID/路径双向可追踪。
- 识别页面、面板、按钮、图标、文本、列表/重复项、装饰、遮罩及潜在交互状态，但不把推测行为
  当作已确认组件契约。

### R2. 未来公共组件目录

- 从公共 FairyGUI 包/组件 XML 确定性生成组件目录：稳定包/资源 ID、组件类型、
  尺寸/伸缩约束、插槽、控制器/页面、状态、过渡、可本地化字段、依赖与版本。
- 为 XML 无法表达的意图提供小型、受审查的外置辅助注解：语义标签、风格族、用途、
  允许变体和预览；不得复制 XML 已有结构形成第二事实来源。
- 匹配综合语义角色、结构签名、插槽/控制器契约、布局、风格和预览相似度；外观相似但行为
  契约不兼容时禁止复用整个组件，可退化为复用其公共图片或子组件。
- 识别 PSD 内重复结构并优先映射到公共列表项/组件实例，不为每个重复项复制一套 XML。

### R3. 未来公共图片目录与去重

- 为公共图片生成稳定目录：ID、尺寸、透明边界、精确哈希、感知指纹、语义/风格/颜色/形状标签、
  九宫格/平铺、对称与允许的镜像方式、伸缩范围、包归属、来源/许可证、引用数和预览。
- 候选检索按安全级别进行：透明边界归一后的精确匹配 → 精确镜像匹配 → 已确认的
  九宫格/平铺重建 → 近似视觉/语义候选。
- 同一基准图片通过 FairyGUI 实例镜像表达水平/垂直/双向镜像；视觉等价时禁止输出镜像
  PNG。识别 PSD 左右/上下对称结构时可以建议“一半图片 + 镜像实例”，但必须检查中缝和非对称细节。
- 九宫格建议必须给出 insets、不可拉伸边角/边框和中心策略，并在原始、目标最小和目标最大尺寸验证；
  渐变、噪声、文字或装饰跨越拉伸区时拒绝自动九宫格。
- 选定基准图片后，应阻止新增精确重复图片；近似图片只能作为带证据的候选，不能仅凭相似度删除
  或替换业务资源。

### R4. 可审查导入计划

- 修改 FairyGUI 事实来源前生成确定性的 `PsdImportPlan`，逐项记录原 PSD 图层 ID/路径、规范语义名、
  目标组件/图片 ID、`pkg/src`、插槽映射、镜像方式、九宫格/平铺、置信度、证据、备选和拒绝原因。
- 计划同时列出：直接复用、变换后复用、组件组合、建议新增、无法表达/需 rasterize、需要决策的项目，
  并给出新增图片数量、节省图片数量/面积和新增包依赖。
- 应用同一输入、同一公共库版本和同一已批准计划必须产生相同 XML/资源；生成文件不是手工事实来源。
- 公共库变更后旧计划不得静默重解释；目录版本/哈希不一致时必须重新匹配或显式迁移。

### R5. 生成、预览与反馈

- 已接受的组件/图片复用生成跨包 `pkg/src` 引用；镜像写为实例镜像；九宫格/平铺写入基准图片
  元数据；仅将未匹配内容导出为规范命名的新资源。
- 生成后运行 XML/引用/ID 检查、精确重复门禁、包依赖/依赖环检查和清单
  过期/确定性检查，再通过已部署的 FGUI Agent Bridge 预览和控制器状态；截图由后续 Unity Agent
  Bridge 的运行时验证提供。
- 对照 PSD 原尺寸，同时在相关组件最小/最大尺寸检查九宫格边角、边缘、中心和镜像中缝；组件复用还要
  验证插槽、控制器页面、文本溢出和交互点击区域。
- 接受/拒绝候选作为项目内、可审查的目录反馈保存；不得把原始 PSD 或私有设计上传到外部
  服务，除非未来另行获得明确授权。

## 不在范围内

- 本子任务不清理、重命名或去重当前仓库的现有图片。
- 不要求 AI 修复或回写设计师的 PSD 图层结构；语义树和映射是独立派生数据。
- 不保证 Photoshop 所有效果都能结构化还原；不可表达效果允许明确栅格化。
- 不用视觉相似度自动删除公共库资源，不建立未经验证的全局“万能组件”。
- 不实现 Unity 运行时 UI 生命周期、GameHot/ET 适配或 UGUI 清理；它只补齐设计输入到 FairyGUI
  事实来源的前置环节。

## 验收标准

- [ ] AC01：含重复名、默认名、错误分组和隐藏/遮罩层的代表 PSD 可生成稳定语义树，每个输出节点可追溯到原图层 ID/路径。
- [ ] AC02：公共组件目录由 FairyGUI XML/辅助注解确定性生成，组件候选显示插槽/控制器/伸缩兼容证据；不兼容组件不会被整体复用。
- [ ] AC03：公共图片目录包含精确匹配、透明边界归一、镜像、九宫格/平铺和语义检索所需元数据，并保留来源与稳定 ID。
- [ ] AC04：精确重复与精确镜像自动映射到基准图片；输出不包含重复或预镜像 PNG，FairyGUI 使用同图实例镜像后截图等价。
- [ ] AC05：九宫格候选在原始、最小和最大尺寸保持边角/边框正确；不安全拉伸区域被拒绝并说明像素证据。
- [ ] AC06：重复 PSD 结构可复用公共组件/列表项实例；结构/行为契约不符时退化而不是强行套用。
- [ ] AC07：`PsdImportPlan` 完整列出复用、变换、组合、新增、栅格化和未解决项，并包含置信度、证据、替代方案、库版本/哈希和资源节省统计。
- [ ] AC08：同一 PSD、公共库版本和已批准计划重复应用不产生非确定性 XML、ID、文件名或图片差异。
- [ ] AC09：生成 XML 仅对未匹配内容新增图片，所有复用项使用稳定 `pkg/src`、实例镜像和九宫格/平铺；检查工具阻止精确重复与失效引用。
- [ ] AC10：FGUI Agent Bridge 预览配合 Unity Agent Bridge 运行时截图能够对比 PSD，检查组件状态、文本、九宫格多尺寸和镜像中缝，并归档证据清单。
- [ ] AC11：公共库升级导致候选契约/哈希变化时旧计划立即失败，不静默改用另一个资源。
- [ ] AC12：原 PSD 全程只读；分析缓存、缩略图和私有设计内容不进入运行时包或未经授权的外部服务。

## 待确认问题

- 近似视觉图片和语义组件候选的自动应用权限尚未确定；精确重复/精确镜像可安全自动复用，
  近似匹配/九宫格/组件复用需要选择审批策略。
