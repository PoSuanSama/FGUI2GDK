# C# 与运行时规范

## 遵循编译器和分析器

将 `Share/Analyzer` 和目标项目的警告即错误设置视为可执行规范。抑制诊断前先检查其实现。优先修复设计；只有确认为误报且记录原因时，才添加范围精确的抑制。

当前重要的 GDK 规则包括：

- 在被分析的游戏/服务端程序集中使用 UniTask，而不是 `Task`；
- 绝不引入 `async void`；仅对有意为之的即发即弃入口使用 `UniTask`、`UniTask<T>` 或 `UniTaskVoid`；
- 在游戏程序集中使用项目日志抽象，不要使用 `UnityEngine.Debug`；
- 分析器要求时，使用项目文本格式化工具；
- 遵循 ET 的 Entity/System 分离、组件/子对象所有权、字段访问、静态状态、消息和客户端/服务端约束；
- 业务代码不得访问以 `__` 开头的生成器内部字段。

当旧文档中的规则与当前分析器或相邻代码不一致时，不要照搬旧规则。

## 匹配现有风格

- 遵循相邻代码和 `Kit.sln.DotSettings` 的命名空间、大括号、`this` 限定、字段前缀、访问修饰符和文件布局。
- 除非本地模式有意将紧密相关的小型类型放在一起，否则每个文件只保留一个主要类型。
- 类型和公共成员使用 PascalCase；序列化/私有字段遵循本地 `m_` 约定。
- 保持方法职责集中。仅在语义重复时提取共享行为，不要只因语法相似就抽象。
- 只为不明显的业务规则、序列化限制、兼容性处理或细微生命周期行为添加简短的简体中文注释。
- 避免将盘符路径、开发者机器路径、魔法 ID、资源路径、端口和调优值散布在业务代码中。使用现有常量/配置，不要创建无意义的包装层。

## 处理异步和生命周期

1. 将长时间运行的工作绑定到所有者生命周期，并在本地 API 支持时提供取消机制。
2. 每次可能超过所有者生命周期的 `await` 之后，重新检查所有者、Entity 或 Unity 对象是否仍然有效。
3. 在对应的关闭、隐藏或销毁生命周期中取消事件订阅、停止计时器、取消请求并释放容器。
4. 不要从工作线程继续调用 Unity API。
5. 通过项目日志/错误通道观察即发即弃任务的失败。
6. 如果容器或 AssetSet 已负责合并和跟踪加载，不要启动重复加载。

## 保护 Unity 序列化

- 没有迁移方案时，不要重命名序列化字段或修改其类型；适用时使用 `FormerlySerializedAs`。
- 除非任务包含迁移，否则保持枚举数值、Luban ID、操作码范围、Entity/UI ID 和序列化默认值稳定。
- 不要序列化仅供运行时使用的缓存、取消源、服务或临时引用。
- 修改组件字段或继承关系后，验证预制体/场景实例。

## 保护帧时间与内存

- 在热点路径中避免每帧分配、LINQ、反射、字符串拼接、重复组件查找和同步资源 I/O。
- 缓存稳定查询，并复用 GDK 的对象池/容器。
- 在帧同步代码中使用确定性/定点数类型；ET 分析器会在需要时禁止浮点状态。
- 声明性能得到提升前先测量。重大性能工作必须提供 Profiler 证据。

## 按所有权设计 API

- 保持公共 API 精简，并明确谁创建、持有、释放和修改对象。
- 优先使用强类型数据和现有领域抽象，避免使用 `object`、字符串分发或全局静态状态。
- 在边界处验证外部、网络和配置数据。
- 明确失败和取消行为；不要静默吞掉异常，也不要在状态已损坏时只记录日志后继续执行。

## 测试行为而非实现细节

针对缺陷修复、解析器、生成器、协议规则、状态转换和可复用辅助逻辑新增或更新测试。Unity 行为使用 Unity Test Framework，或按照已安装 Bridge 契约使用 `AgentCallable` 流程。隔离测试资源，并在 `finally` 中清理临时状态。
