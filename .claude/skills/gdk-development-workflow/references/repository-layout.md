# 仓库目录与归属规范

## 按运行时边界放置变更

| 区域 | 归属与约束 |
| --- | --- |
| `DotNet/App` | 服务端入口与可执行程序装配。不要放置业务逻辑。 |
| `DotNet/Core` | 服务端框架基础能力，保持最小依赖面。 |
| `DotNet/Model` | 服务端 Entity 和状态。适用 ET 分析器规则。 |
| `DotNet/Hotfix` | 可热更新的服务端行为和 System。 |
| `DotNet/Loader` | 服务端加载/引导行为。 |
| `DotNet/ThirdParty` | 外部集成边界。仅在明确的依赖任务中修改。 |
| `Share/Analyzer` | 可强制执行的 Roslyn 规则和代码修复。稳定语义规则优先实现为分析器。 |
| `Share/SourceGenerator` | 编译期生成的 ET 代码。变更后测试使用方。 |
| `Share/Tool` | Luban、Proto、Excel 和其他开发工具。 |
| `Unity/Assets/Scripts/Game` | 非热更新客户端框架与共享游戏集成。 |
| `Unity/Assets/Scripts/Game/Hot/Code` | 可由 HybridCLR 热更新的 GameHot 业务代码。 |
| `Unity/Assets/Scripts/Game/Hot/Loader` | 不可热更新的 GameHot 引导代码。不要放置依赖热更新的行为。 |
| `Unity/Assets/Scripts/Game/ET/Code` | ET 的 Model、ModelView、Hotfix、HotfixView、共享、客户端和服务端代码。 |
| `Unity/Assets/Scripts/Game/ET/Loader` | 不可热更新的 ET 加载与 UGF 集成。 |
| `Unity/Assets/Scripts/Game/Editor` | 仅供 Editor 使用的项目工具；运行时程序集不得引用 `UnityEditor`。 |
| `Unity/Assets/Scripts/Library` | 框架和第三方代码。优先在 `Game` 中使用扩展点，避免修改供应商代码。 |
| `Unity/Assets/Res` | 已导入的运行时/Editor 资源。遵循 `asset-management.md`。 |
| `Design/Excel` | Luban 和本地化源数据。 |
| `Design/Proto` | 协议源文件及 `proto.conf` 的归属目录。 |
| `Tools` | 构建/导出脚本和内置工具链。避免附带修改工具二进制文件。 |
| `Book` | 持续维护的项目文档。工作流或公共行为变化时同步更新。 |

## 有意识地选择 ET 或 GameHot

创建 UI、Entity、Procedure、消息或玩法代码前，根据相邻代码和目标运行时确定当前实现模式：

- 功能属于 GF/MonoBehaviour 热更新路径时，使用 GameHot 模式。
- 数据/视图 Entity 使用 ET Model/ModelView，System 和行为使用 Hotfix/HotfixView。
- 服务端专用代码不得进入客户端程序集，客户端命名空间不得进入服务端程序集。
- 共享协议/数据代码必须保持确定性，并且不依赖仅客户端可用的 Unity API。
- 除非任务明确要求两套实现一致，否则不要在 ET 和 GameHot 中重复实现同一功能。

## 遵守程序集边界

1. 添加依赖前，检查最近的 `.asmdef` 或 `.csproj`。
2. 将 Editor 代码放在 Editor 程序集或 Editor 文件夹中。
3. 避免循环引用，不要为了一个辅助方法添加宽泛的程序集引用。
4. 使用所涉及目标程序集中最低的语言版本：`Unity/Directory.Build.props` 中 Unity 默认为 C# 11；当前 .NET 项目明确使用 C# 12。
5. 仅在代码裁剪/AOT 证据表明确有需要时，更新 `link.xml`、AOT 泛型引用或 HybridCLR 元数据。

## 将生成输出视为派生状态

不要手动编辑：

- 路径中包含 `/Generate/` 且由 Luban、Proto2CS、源生成器或 Editor 工具生成的文件；
- 标记为 `<auto-generated>` 的文件；
- CodeBind 生成的 `*.Bind.cs`；
- 从 Excel 生成的强类型 UI/Entity/Sound/Scene ID；
- 生成的本地化键和数据行。

先修改 `Design/` 下的来源、生成器模板/配置或所属预制体绑定，再重新生成。源码和输出都必须审查。如果无法运行生成流程，停止并报告缺失的前置条件，不要修补派生文件。

## 谨慎添加新的顶层概念

优先使用现有业务领域文件夹和本地命名空间。只有当新文件夹或程序集能形成真实的所有权边界、编译边界或可复用模块时才添加，并将其 `.asmdef`、命名空间、测试、文档和 Unity `.meta` 纳入同一变更。

## 避免仓库噪声

绝不提交 Unity `Library`、`Temp`、`Logs`、`UserSettings`、生成的 IDE 项目、本地数据库状态、构建输出、Excel 临时锁文件或 Editor 缓存。不要为了让差异看起来干净而修改被忽略的输出。
